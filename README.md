# ProcessBlacklist

[English](README.en.md) · [بیلدهای آزمایشی](https://github.com/Mehrdad32/ProcessBlackList/actions/workflows/ci.yml) · [گزارش مشکل](https://github.com/Mehrdad32/ProcessBlackList/issues)

> این شاخه قدم اول بازسازی نسخهٔ **2.0.0-alpha.1** است. برای تست و بازخورد آماده می‌شود؛ نسخهٔ پایدار قبلی تا تأیید این مرحله روی `master` حفظ شده است.

ProcessBlacklist قوانین نام پردازش‌ها را روی ویندوز پایش می‌کند. می‌توانی نتیجهٔ قوانین را در **Preview** ببینی و سپس بستن خودکار پردازش‌های مطابق را فعال کنی.

## دریافت و اجرا

در [Actions](https://github.com/Mehrdad32/ProcessBlackList/actions/workflows/ci.yml)، آخرین اجرای موفق شاخهٔ `feat/v2-rebuild` را باز کن و artifact مناسب را بگیر:

| سیستم | Artifact |
| --- | --- |
| ویندوز ۶۴ بیتی | `ProcessBlacklist-win-x64` |
| ویندوز ۳۲ بیتی | `ProcessBlacklist-win-x86` |
| تصاویر UI با دادهٔ نمونه | `ProcessBlacklist-ui-preview` |

ZIP را استخراج و `ProcessBlacklist.exe` را اجرا کن. خروجی‌ها .NET را همراه دارند و نصب جداگانهٔ runtime لازم نیست. هدف برنامه ویندوز دارای پشتیبانی [.NET 10](https://learn.microsoft.com/en-us/dotnet/core/install/windows) است.

برنامه با دسترسی معمول کاربر اجرا می‌شود. اگر ویندوز اجازهٔ دسترسی به پردازش موردنظر را نداد، می‌توانی آن را با **Run as Administrator** اجرا کنی. برنامه خودش نسخهٔ دیگری با دسترسی مدیر باز نمی‌کند.

## استفاده

1. در فهرست پردازش‌ها جست‌وجو کن و با **Use selected name** نام را به ورودی قانون منتقل کن، یا نام را خودت بنویس.
2. حالت **Exact name** یا **Name contains text** را انتخاب و **Add rule** را بزن. پسوند `.exe` اختیاری است؛ تطبیق به حروف بزرگ/کوچک حساس نیست.
3. **Start preview** را بزن. ستون Matches و تب Activity نشان می‌دهند چه پردازش‌هایی مطابق‌اند و کدام‌ها قابل اقدام نیستند.
4. **Stop** را بزن. برای بستن خودکار، گزینهٔ **Terminate matching processes** را انتخاب و **Start termination** را تأیید کن.

Exact name همهٔ نمونه‌های دارای همان نام را تطبیق می‌دهد، نه فقط یک PID. Contains روی بخشی از نام اعمال می‌شود؛ مثلاً `pad` می‌تواند `notepad` و `phonepad` را تطبیق دهد. مسیر فایل، wildcard و regex در این مرحله پشتیبانی نمی‌شوند. اگر چند قانون مطابق باشند، اولین قانون فعال مسئول همان پردازش است.

**Preview پردازشی را نمی‌بندد. Termination بستن اجباری است و دادهٔ ذخیره‌نشدهٔ برنامهٔ هدف ممکن است از دست برود.** پیش از فعال‌کردن آن، نتیجهٔ قوانین را در Preview بررسی کن.

## کنترل‌ها

| کنترل | رفتار |
| --- | --- |
| Start preview | پایش قوانین و نمایش نتیجه، بدون درخواست بستن |
| Start termination | پایش و درخواست بستن پردازش‌های مطابق، پس از تأیید کاربر |
| Stop | جلوگیری از اقدامات بعدی و انتظار برای پایان عملیات جاری |
| Refresh | بازخوانی پردازش‌ها هنگام توقف پایش |
| Add rule | اعتبارسنجی و ذخیرهٔ قانون؛ پایش را شروع نمی‌کند |
| Enable / disable | تغییر وضعیت قانون و ذخیرهٔ آن |
| Remove rule | حذف قانون و ذخیرهٔ تغییر |
| End selected… | بستن همان هویت پردازش انتخاب‌شده، با تأیید جداگانه |
| Reset counters | صفرکردن شمارنده‌های همین نشست |
| Minimize to tray | مخفی‌کردن پنجره در tray؛ پایش فعال ادامه دارد |
| Settings folder | بازکردن محل ذخیرهٔ قوانین |

برای ویرایش قوانین، حالت و فاصلهٔ بررسی، ابتدا پایش را Stop کن. اجرای دوبارهٔ برنامه همیشه با پایش متوقف و Preview انتخاب‌شده شروع می‌شود. بستن معمول پنجره پایش را متوقف می‌کند؛ Minimize to tray آن را متوقف نمی‌کند.

## هویت پردازش و نتیجهٔ عملیات

- PID، زمان ایجاد و مسیر فایل قبل از بستن دوباره بررسی می‌شوند. بررسی و بستن با همان handle انجام می‌شوند تا PID بازیافت‌شده به پردازش دیگری اشاره نکند.
- خود برنامه، شناسه‌های رزروشده، نام‌های حساس ویندوز و پردازش‌هایی که ویندوز critical اعلام می‌کند بسته نمی‌شوند.
- اگر هویت یا وضعیت critical قابل بررسی نباشد، آن پردازش کنار گذاشته می‌شود. خطای دسترسی برای یک پردازش، پایش بقیه را متوقف نمی‌کند.
- ستون **Closed** فقط خروج تأییدشده توسط ویندوز را می‌شمارد. `Pending` یعنی درخواست ثبت شده ولی خروج در ۱٫۵ ثانیه تأیید نشده است.
- Stop درخواست بستن صادرشده را برنمی‌گرداند؛ ادامهٔ کار را متوقف می‌کند. این برنامه سرویس، درایور یا ابزار جلوگیری از اجرای فایل نیست؛ پردازش پس از اجرا و در نوبت بررسی شناسایی می‌شود.

## تنظیمات و Activity

قوانین و فاصلهٔ بررسی در `%LOCALAPPDATA%\ProcessBlacklist\settings.json` ذخیره می‌شوند. ذخیره ابتدا در فایل موقت و سپس با جایگزینی فایل انجام می‌شود. دادهٔ نامعتبر یا نسخهٔ ناشناخته هنگام بارگذاری بازنویسی نمی‌شود؛ خطا و راه بازیابی داخل برنامه نشان داده می‌شود.

شمارنده‌ها و Activity مربوط به نشست فعلی‌اند. Activity حداکثر ۳۰۰ ردیف نگه می‌دارد و نتیجهٔ تکراری یک پردازش را در نوبت‌های پیاپی دوباره اضافه نمی‌کند.

## ساخت و تست

برای ساخت کامل، ویندوز و **.NET 10 SDK** لازم است:

```powershell
dotnet build ProcessBlacklist.slnx -c Release
dotnet run --project tests/ProcessBlacklist.Core.Tests -c Release
dotnet run --project tests/ProcessBlacklist.Windows.Tests -c Release
dotnet run --project tests/ProcessBlacklist.Ui.Smoke -c Release -- ui-preview
```

runnerها با `dotnet run` اجرا می‌شوند، نه `dotnet test`. تست‌های Core و UI از پردازش‌های شبیه‌سازی‌شده استفاده می‌کنند. تست native ویندوز فقط childهایی را می‌سازد و می‌بندد که متعلق به خود تست‌اند.

| بخش | مسئولیت |
| --- | --- |
| `src/ProcessBlacklist.Core` | قوانین، اعتبارسنجی، ذخیرهٔ JSON، Preview و اجرای پایش |
| `src/ProcessBlacklist.Windows` | خواندن و بررسی هویت و بستن با handle ویندوز |
| `src/ProcessBlacklist.App` | رابط WinForms، فهرست‌ها، Activity و tray |
| `tests` | regressionهای Core، native و UI |
| `legacy/v1` | سورس تاریخی ۲۰۱۹، خارج از بیلد جدید |
